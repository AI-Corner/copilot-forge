## 1. Feature Overview
Understanding how Copilot Forge translates a simple `#forge-proceed` command into a multi-agent, context-aware workflow can seem like magic. This document breaks down the exact mechanics of how prompts, agents, templates, rules, and knowledge are invoked and injected under the hood.

---

## 2. The Core Flow Mechanics

### A. How Main Prompts Are Invoked
You (the user) only ever interact with the "Main Prompts" (e.g., `#forge-init`, `#forge-proceed`). The invocation flow is handled natively by GitHub Copilot:

1. **The Switch**: Your `.vscode/settings.json` must contain `"github.copilot.chat.experimental.prompt-files.enabled": true`. This tells the Copilot extension to look for custom prompt files in the repository.
2. **The Directory Scan**: Once enabled, Copilot automatically scans the `.github/prompts/` directory when the workspace loads, looking for any file ending in `.prompt.md`.
3. **The Registration**: When it finds a file like `forge-init.prompt.md`, it registers the first part of the filename (`forge-init`) as an accessible command in the chat interface. That is why typing `#forge-init` auto-completes.
4. **The Invocation**: When you type `#forge-init`, the Copilot Chat extension does not just send your text to the LLM. Instead, it natively intercepts that command, reads the entire content of `.github/prompts/forge-init.prompt.md`, and **injects it as the hidden system prompt** for that conversation turn. It basically tells the AI behind the scenes: *"Pretend you are the agent described in this markdown file, follow these specific instructions step-by-step, and here is the user's input."*

### B. When Agents Are Called
You **never** invoke agents (like the security auditor or architecture reviewer) directly. 
Instead, it is a "prompt calling other prompts" architecture. The main orchestrator prompt you invoked acts as the manager. For example, if you run `#forge-proceed`, that prompt will get to Phase 5 and explicitly tell the LLM: *"Now, go read the file at `.github/prompts/agents/security-auditor.prompt.md` and do what it says to check the code."* 

### C. When Templates Are Used
Whenever a prompt needs to create a new file (like a new Requirement spec, a new Task, a new Bug report, or a new Lesson), it does not hallucinate the structure. It is explicitly instructed to go look in `.forge/templates/` first. It reads the canonical template (e.g., `requirement-template.md`), copies that exact structure, and just fills in the blanks. This ensures that every file generated by the AI is perfectly structured, predictable, and doesn't suffer from formatting drift over time.

## 3. Context Injection: Rules vs. Corpus

The `.forge/context/` files are not active "agents" that *do* things; they are **memory and constraints**. They are injected into the flow during the **Prerequisites** or **Context Gathering** steps of the main prompts (e.g., telling the LLM to read `.forge/context/rules/architecture.rules.md` before making any decisions).

*   **Rules (`.rules.md`)**: These are condensed, strict, unbreakable constraints. They are injected into almost every fast-moving prompt (like TDD or Implementation) because they consume very few tokens and keep the AI strictly on rails.
*   **Corpus (`.md`)**: These are long-form, verbose explanations. The AI only reads these if it is doing deep planning (like `#forge-spec`) or if it encounters a rule it doesn't fully understand and needs the historical background.

## 4. Verification: Computational vs. Inferential Agents

Copilot Forge cleanly splits verification (Phase 5 of the pipeline) into two parts to save time, money, and LLM hallucination.

*   **Part 1: Computational Sensors (Fast & Deterministic)**
    *   **Location:** `.github/prompts/agents/computational/`
    *   **What they are:** These are essentially shell commands that yield a binary PASS/FAIL (e.g. `lint-gate`, `test-gate`, `build-gate`).
    *   **The Rule:** They run **first**. If *any* computational sensor fails, the pipeline halts immediately. The agent is forced to fix the syntax error or failing test before doing anything else.
*   **Part 2: Inferential Sensors (Slow, LLM-based Heuristics)**
    *   **Location:** `.github/prompts/agents/inferential/`
    *   **What they are:** These are actual LLM personas that read your code and use reasoning to catch logic flaws, architectural drift, or security vulnerabilities (e.g., "Is this SQL injection safe?").
    *   **The Rule:** They run **second**, and *only* if the Computational Sensors passed 100%. There is no point spending expensive LLM tokens asking an AI to review the "architecture" of a file if that file has a missing semicolon and won't even compile!

## 5. Knowledge Retrieval (RAG)

We **do not** inject all support or lesson documents into every prompt. If we injected every single lesson, bug, and support document, we would instantly blow up the LLM's context window and cause it to lose focus (the "Needle in a Haystack" problem).

Instead, Copilot Forge uses a **Weighted-Score Retriever (RAG)** at context-loading time:
1.  The algorithm looks at the YAML frontmatter of the current task (e.g., `domain: architecture`) and compares it to the frontmatter of the files in `.forge/knowledge/`.
2.  It assigns points: `+3` points for an exact component match, `+2` points for a domain match, `+2` points for overlapping concerns, and `+1` point for overlapping tags.
3.  Only the **Top 15** highest-scoring documents are actually injected into the LLM's context for that specific prompt run.

**Targeted Retrieval:**
Not every prompt asks for the same type of knowledge. The prompts themselves explicitly declare *which* folders they want the retriever to scan:
*   `#forge-spec`: Retrieves from `lessons/`, past `specs/`, and resolved `bugs/` so it doesn't repeat past mistakes during planning.
*   `#forge-architect` & `#forge-review`: Mostly focused on the "Why", so they retrieve heavily from `lessons/`.
*   `#forge-query`: This is the general Q&A agent, so it retrieves from both `lessons/` and `support/`.

You cannot guarantee that *all* support or knowledge is injected. You can only guarantee that the Top 15 most mathematically relevant files are injected based on the frontmatter tags.
